QRPC Calculator

Interactive tool for the Qualitative Rectilinear Projection Calculus

Labelling convention. Throughout the application, objects are labelled 1, 2 and 3 (rather than i, j and k as in the research paper). Accordingly, relation names use numeric subscripts: R12 instead of Rij, and component names use numeric indices: C12O1FB instead of CijOiFB.

Introduction

The QRPC Calculator is an interactive tool for exploring the Qualitative Rectilinear Projection Calculus, a spatial reasoning algebra that describes the relative position and orientation of two oriented objects whose rectilinear projections onto a common reference axis are considered.

The algebra defines 48 basic relations (BRs) that partition the configuration space of any pair of objects into mutually exclusive, jointly exhaustive categories (JEPD), and supports two core algebraic operations:

  • Converse — swaps the roles of the two objects: R12 → R21.
  • Composition — derives R13 from R12 and R23 via weak composition over the finite relational language.

The application has four main tabs: Relations, Neighbourhood, Converse, and Composition. The Composition tab contains four internal sub-tabs: Geometric viewer, Rules Table (24×24), PC-2 verification, and Associativity. Every panel with a ? button opens this manual at the relevant section.

Quick start: open Relations and drag the objects to see a live relation. Switch to Neighbourhood to explore geometric adjacency between basic relations. Switch to Converse to observe the role swap. Then open Composition → Geometric viewer to explore how three objects compose.

Notation

Every basic QRPC relation is a tuple of six qualitative components. Each component captures a distinct geometric aspect of the spatiotemporal configuration between two oriented objects 1 and 2:

ComponentSymbolDomainMeaning
P12Projection type X, ↑↑, ↑↓, ↑, ↕ Relative arrangement of the rectilinear projections of objects 1 and 2: X = crossing; ↑↑ = parallel same direction; ↑↓ = parallel opposite; ↑ = overlapping same direction; ↕ = overlapping opposite direction.
C12O1FBC12O1FB +, 0, − Position of the intersection point C12 with respect to the front–back dichotomy of object 1: (+) = in front, (−) = behind, (0) = at the origin of object 1.
C12O2FBC12O2FB +, 0, − Position of C12 with respect to the front–back dichotomy of object 2.
O12LRO12LR +, 0, − Lateral position of object 1 with respect to the left–right dichotomy of object 2: (+) = to the right, (−) = to the left, (0) = on the projection line.
D12LRD12LR +|−, −|+, 0|+, +|0, 0|−, −|0, 0|0 Qualitative representation of the lateral motion of object 1 with respect to the rectilinear projection of object 2. The first value indicates the region from which object 1 comes; the second indicates the region toward which it is moving. (+) and (−) denote the right and left regions respectively; (0) denotes the intersection point C12.
O12FBO12FB +, 0, − Position of object 1 with respect to the front–back orientation of object 2 when a virtual overlap of their rectilinear projections is performed: (+) = object 1 in front of object 2, (−) = behind, (0) = same position.

Some components exhibit ambivalence — they take two simultaneous values — when the geometric configuration places them at a qualitative boundary (e.g. C12O2FB = 0, or P12 ∈ {↑↑, ↑↓, ↑, ↕}. These ambivalent states are resolved through their conceptual neighbourhood transitions.

Relation display formats

Throughout the application, basic relations can be displayed in three formats:

  • Instantiated representation — the complete six-component tuple, showing all six qualitative components explicitly, in the order ⟨P12, C12O1FB, C12O2FB, O12LR, D12LR, O12FB⟩. This format is shown in the Signature diagram sub-panel of the Geometry editor.
  • Canonical representation — retains only the components necessary to identify the relation unambiguously; components inferrable from the remaining ones are replaced by an underscore (_). This is the relational vocabulary of QRPC as defined in the research paper (Table 1). It is the primary format used in all panels, selectors, and result tables.
  • Compact form — a purely typographic reorganisation of the canonical representation using superscripts and subscripts (e.g. X+−+−). It carries no additional information beyond the canonical representation. Used in the Neighbourhood graph node labels and in the 24×24 composition rules table headers.

Example: relation <X,+,−,+,_,−>

The following shows the same basic relation in its three representations:

Representation Form Notes
Instantiated representation ⟨X, +, −, +, +|0, −⟩ All six components explicit. D12LR = +|0 means object 1 is approaching C12 from the right.
Canonical representation (in-line text) <X, +, −, +, _, −> D12LR is replaced by _ because it is fully determined by O12LR = − in a crossing (X) configuration: object 1 must be moving toward C12, so D12LR is always +|0.
Compact form X+−+− Superscripts encode C12O1FB and C12O2FB; subscripts encode O12LR and O12FB. The omitted D12LR does not appear.

Note: relations in the PAR and OVL families may admit more than one instantiated representation due to geometric ambivalence — when the configuration sits at a qualitative boundary, two component values are simultaneously valid. The canonical representation and compact form are unique in all cases.

Canonical representation and its compact form

The canonical representation is the primary display format across the application — selectors, result tables, converse table, and composition panels all show relations in canonical form (e.g. <X,+,−,+,_,−>). The compact form is a purely typographic reorganisation of the canonical representation using superscripts and subscripts — e.g. X⁺⁻+− — and is used in the Neighbourhood graph node labels and in the 24×24 composition rules table column and row headers. The instantiated representation (all six components explicit, no wildcards) appears only in the Signature diagram sub-panel of the Geometry editor, where it shows the context-specific realisation of the identified relation.

Relations tab

An interactive canvas where two oriented objects 1 (blue) and 2 (red) can be freely positioned and rotated. The basic relation is identified in real time and displayed in the right panel.

The Relations and Converse tabs share the same pair of objects: moving an object in either tab updates the other simultaneously.

Operational frontier capture. In the Relations tab, X-family boundary states near θ=0, θ=π, φ=0 or φ=π are visualised using a small internal tolerance band. This does not change the mathematical definition of QRPC states; it only prevents frontier configurations from being absorbed by a neighbouring interior state due to numerical tolerances.

Neighbourhood tab

The Neighbourhood tab displays the geometric neighbourhood graph of the 48 QRPC basic relations. Two relations are geometric neighbours if their regions in the parameter space share a boundary — a continuous movement of the observed objects can transition between them without crossing a qualitative category boundary. There are no direct transitions between PAR and OVL families; all such transitions pass through an X-family relation.

The graph has 48 nodes and 128 neighbour pairs (average 5.3 neighbours per BR). Node labels use the compact notation from the paper — superscripts for C12O1FB and C12O2FB, subscripts for O12LR, D12LR and O12FB — as this is the format used in the published neighbourhood tables. The five families are colour-coded:

AmberParallel opposite direction↑↓
PurpleOverlapping same direction↑
RedOverlapping opposite direction↕

Interaction

  • Click a node to select it. The selected node is highlighted in its family colour (filled), its neighbours are shown with a darker fill, and all other nodes and edges are dimmed.
  • Click again on the selected node to deselect it and restore the full graph.
  • Hover over a node to see its canonical form in a tooltip.
  • The Reset button clears any selection and restores the full graph.
  • The Detail panel on the right shows the selected relation in canonical form, its family name, and the complete list of its geometric neighbours — each tagged with its own family colour.
  • The graph lives inside a scrollable area; use the scroll bars to navigate if the window is smaller than the canvas.

Converse tab

The Converse tab visualises the converse operation. It reuses the same pair of objects as the Relations tab. If R12 describes the spatial configuration of object 1 with respect to object 2, the converse R21 describes the same configuration as seen from object 2's perspective — the two objects swap roles while the physical geometry remains unchanged. The converse operator is involutive and strong: (r̆)̆ = r and it preserves exact semantic equivalence without over-approximation.

Composition tab

The Composition tab is the core algebraic workspace. It contains four sub-tabs accessible via the tab bar at the top of the panel:

Sub-tabPurpose

Algebraic foundation. QRPC composition is defined as weak composition: R₁₂ ⋄ R₂₃ = ∪{Rk | φ(Rk) ∩ (φ(R₁₂) ∘ φ(R₂₃)) ≠ ∅}. The composition table is derived from a minimal generating subset Z of canonical representatives and seven π-rotation transformation rules that exploit the spatial symmetries of the calculus. Every entry satisfies the path-consistency conditions by construction.

Composition — PC-2 verification

Verifies that the geometric construction is sufficiently precise for all 27,056 ordered triplets in the full composition space X to satisfy the path-consistency conditions. The 288 canonical Z entries form a minimal generating set: verifying Z is sufficient to certify the full X space, since every pair in X is reachable from a Z entry via the 7 π-rotation rules.

cond. 2: R₁₂ ∈ r₁₃ ∘ R₃₂ — R₁₂ must be recoverable by composing r₁₃ with conv(R₂₃).
cond. 3: R₂₃ ∈ R₂₁ ∘ r₁₃ — R₂₃ must be recoverable by composing conv(R₁₂) with r₁₃.

Missing-triplet analysis

Answers the question: which path-consistency checks fail if a given Z triplet is removed from the verification basis? Select one of the ~3,382 canonical Z triplets, run the analysis, and the table shows all affected triplets tagged as Z (part of the canonical generating set) or X∖Z (in the full composition space but not in Z).

Clicking any row in the table opens a detail panel showing the path-consistency analysis under the reduced basis — that is, the same verification that the full algebra passes, but with the omitted seed and its entire π-orbit removed. The panel shows:

  • Which condition (cond. 2 and/or cond. 3) fails under the reduced basis.
  • The reduced composition set — the result of the supporting composition after removing the omitted triplets — and why the required basic relation is no longer present.
  • A conclusion explaining how removing the seed propagates to this triplet through the π-orbit.

Tip: Triplets labelled Z are directly part of the generating set and typically fail because the omitted seed is the canonical representative itself (rule 0) or one of its π-images (rules 1–7). Triplets labelled X∖Z fail because they depend on the omitted orbit as their only supporting composition path in the full space.

Composition — Triplet inspector

The Triplet inspector gives direct, search-free access to the path-consistency analysis for any specific triplet (R₁₂, R₂₃, r₁₃), without having to browse the missing-triplet analysis tab.

How to use it

  1. Select R₁₂ and R₂₃ from the two drop-down selectors. The composition R₁₂ ∘ R₂₃ is computed immediately and displayed as a set of basic relations.
  2. Choose one result relation r₁₃ from the third selector. Only relations that belong to the composition result are listed — invalid combinations cannot be selected.
  3. Click Analyse triplet to run the full path-consistency verification.

Reading the result

ConditionFormulaMeaning
cond. 2 R12 ∈ r13 ∘ R32 R12 must appear in the composition of r13 with conv(R23). The known relation between objects 1 and 2 is recoverable from the inferred r13.
cond. 3 R23 ∈ R21 ∘ r13 R23 must appear in the composition of conv(R12) with r13. The known relation between objects 2 and 3 is recoverable from the inferred r13.

Both conditions must hold for the triplet to be PC-consistent. The status bar shows a ✓/✗ summary; the full composition sets are listed in the result area for inspection.

Tip: All valid QRPC triplets satisfy all path-consistency conditions. Use this panel to cross-check any triplet of interest — for example one found in the Geometric viewer or the Rules Table — without running a full verification pass.

Composition — Associativity

Checks whether (R₁₂ ∘ R₂₃) ∘ R₃₄ = R₁₂ ∘ (R₂₃ ∘ R₃₄). QRPC weak composition is not universally associative — this is expected for calculi based on weak representation. Associativity is not required for path-consistency inference, which operates locally over relational triads.

Single triplet sub-tab

  1. Select R₁₂, R₂₃, R₃₄ from the three drop-downs.
  2. Click Check associativity.
  3. The result panel shows both intermediate compositions, both final sets, and any differing relations.
  4. Click Copy to copy the full text to the clipboard.

Full 48³ scan sub-tab

  1. Click Run full 48³ scan.
  2. A progress bar tracks computation (typically a few seconds).
  3. The result table lists every non-associative triplet.
  4. Click any row to see the full breakdown in the detail panel.
  5. Click Export report to save the full list to a text file.

Known result: QRPC fails associativity for 10,496 of the 110,592 valid triplets (48³). Of these, 93.3% exhibit a subset relationship (one grouping is a superset of the other) rather than genuine incompatibility. This does not affect path-consistency inference.

Reference — The 48 Basic Relations

The 48 QRPC basic relations partition the configuration space of any pair of oriented objects into mutually exclusive, jointly exhaustive (JEPD) categories. They are organised into five families according to the projection type P12:

X (Crossing)X32 The rectilinear projections of objects 1 and 2 cross at a finite point C12. All six components are active. These 32 relations cover the full combinatorics of (C12O1FB, C12O2FB) ∈ {+,−}², O12LR ∈ {+,0,−}, and O12FB ∈ {+,0,−}, with the intersection point D12LR motion component determined by the geometry.
↑↑ (PAR same)↑↑6 Parallel projections in the same direction. C12 is at ±∞, producing ambivalent C12O1FB / C12O2FB values. The six relations differ in O12LR ∈ {+,−} and O12FB ∈ {+,0,−}.

Converse table

The converse operation is involutive (r̆)̆ = r and strong (no over-approximation). Key patterns:

  • X-family relations: the converse swaps the roles of objects 1 and 2, which exchanges C12O1FB↔C12O2FB, reflects O12LR, and may modify D12LR and O12FB through the geometric transformation.
  • PAR relations (↑↑, ↑↓): converse within the same family, swapping O12LR sign.
  • OVL relations (↑, ↕): converse within the same family.
  • All 48 relations satisfy: the converse is a basic relation (no general relation needed).

The full converse table can be viewed and verified in the Converse tab using the algebraic selector, or in the PC-2 verification panel.

Reference — π-Rotation Transformation Rules

Any QRPC composition R₁₃ = R₁₂ ∘ R₂₃ can be mapped to another equivalent composition by applying a combination of π-rotation transformations to the objects involved. A π-rotation inverts the front-facing direction of one object, modifying the components of its basic relation through the functional mappings TP, TD and TD*.

Basic π-rotation cases

For a binary relation R₁₂ between objects 1 and 2, three cases arise:

CaseDescriptionComponents affected
α (1π only)Only object 1 is π-rotated P12, C12O1FB, D12LR via TD*α
β (2π only)Only object 2 is π-rotated P12, C12O2FB, O12LR, D12LR via TD*β, O12FB
γ (both)Both objects are π-rotated P12 is invariant; C12O1FB, C12O2FB, O12LR, D12LR via TD*γ, O12FB all transform

The seven composition transformation rules

Given three objects and a composition R₁₃ = R₁₂ ∘ R₂₃, seven transformation rules map it to an equivalent composition in the generating subset Z:

RuleNotationTransformation appliedEffect on R₁₃
11π23R₁₂ → R₁₂αR₁₃ → R₁₃α
212π3R₁₂ → R₁₂β, R₂₃ → R₂₃αR₁₃ unchanged
3123πR₂₃ → R₂₃βR₁₃ → R₁₃β
41π2π3R₁₂ → R₁₂γ, R₂₃ → R₂₃αR₁₃ → R₁₃α
512π3πR₁₂ → R₁₂β, R₂₃ → R₂₃γR₁₃ → R₁₃β

Rule 0 (label "0" in the Rules Table) means the composition already belongs to Z and can be looked up directly without any transformation.

Generating subset Z

The generating subset Z is a minimal set of 288 canonical composition representatives such that every composition in the full 48×48 space X can be derived from one element of Z by applying one of the seven transformation rules. The construction of Z is guided by the conceptual neighbourhood between basic relations and by shared geometric structures that enable derivation of some compositions from others.

Each element of Z is characterised explicitly through a geometric procedure based on topological partitioning of the rectilinear projections P1 and P3, as described in §4.3–4.5 of the paper. The Rules Table (24×24) in the Composition sub-tab shows which rule applies to each pair of the 24 equivalence classes, providing an efficient lookup mechanism at runtime.

Algorithmic retrieval — GUI. Given any composition R₁₂ ∘ R₂₃, the GUI algorithm: (1) looks up the rule number from the 24×24 table; (2) if rule = 0, retrieves the general relation directly from Z; (3) otherwise applies the π-transformation to the input pair, retrieves the canonical Z result, then applies the inverse rotation to each basic relation in the result to recover the final R₁₃. This derivation is visible step by step in the Rules Table sub-tab detail popup.

Algorithmic retrieval — experimental PC-2. The A(n,d,l) random instance generator of Renz and Nebel (2001), implemented in experiments/run_experiment.py, uses a different, more efficient strategy optimised for repeated inference over large random networks. At startup it calls _precompute(), which iterates over all 48×48 pairs once, calls compose() for each pair, and encodes the result as a 48-bit bitmask — one bit per basic relation — stored in a 48×48 integer matrix COMP_TABLE. The converse of each relation is similarly encoded in a CONV_TABLE of 48 integers. This precomputation takes approximately 0.3 s and is performed once before any trial begins.

During each PC-2 run, constraint propagation reduces to pure bitwise operations: composing two relation sets a and b (each a bitmask) is compose_masks(a, b) — a single integer OR over the precomputed rows — and intersection is a bitwise AND. Each PC-2 iteration updates Rij ← Rij ∩ (Rik ∘ Rkj) for all triples (i, k, j) in the network, repeating until no change occurs. The O(1) lookup per composition makes this implementation fast enough to run hundreds of trials per condition within the benchmark.
